## 发现与修正

| 发现 | 风险 | 修正归属 |
| --- | --- | --- |
| access 的“配置工具”可能被读成唯一指定 | 一个关联被升级为强制选择，影响现有复用规则 | Domain 与样例明确关联不是独占选择、排序或授权；生成指引同步说明 |
| 配置修改和发布恢复的界线未写明 | 同步失败时错误撤销已成功的注册或作者修改 | 样例分开报告配置与发布结果，恢复只作用于本次发布变更 |
| 缺少发布目标与来源重叠检查 | 显式输出路径仍可能覆盖源资料、配置或恢复依据 | 样例补充目标重叠与别名检查，不因此增加文件系统沙箱 |
| 恢复依据何时保存、丢失后如何重建不明确 | 写到一半才发现没有原内容，或把可重建当成接管授权 | 写前保留依据；恢复资料丢失不影响阅读，可用新授权空目标重建，不默认接管旧文件 |
| 工程规范仍使用旧领域的专有名称 | 后续实现可能把旧 Local Bindings / Checkout 恢复成前置模型 | Engineering 改用本机位置、观察与来源，不改变原有隔离和不静默改写原则 |

## 场景推演

下面是对设计规则的检查，不是已执行的应用测试：

| 情况 | 设计应给出的结果 |
| --- | --- |
| Agent 只获得入口文件，DevMeld 未运行 | 可沿已生成链接阅读；不宣称来源永远可用或任意客户端自动加载 |
| 服务恰好只关联一个工具 | 显示关联和使用前提，不自动推导独占选择、当前可用性或安装授权 |
| 注册修改成功，随后同步校验失败 | 配置保持已成功状态，输出不变，明确产物尚未更新 |
| 发布中断，回滚目标又被人修改 | 不覆盖人的新改动，报告待恢复；不能宣称跨文件发布始终原子 |
| 把输出目录设成上下文根，或入口指向源资料 | 因来源/目标重叠而拒绝，不因路径被配置就覆盖 |
| 发布记录丢失，但产物还在 | 阅读不受阻；重新接管不能靠目录名称猜测，可选择新授权空目标重建 |
| 增加一个自定义描述字段 | 在通用描述及所选 Schema 的范围内校验、呈现，不新增业务资源专用领域 |
| 无变化同步或删除资源注册 | 前者不制造知识变化；后者撤下相关产物，不删除原文档或脚本 |
